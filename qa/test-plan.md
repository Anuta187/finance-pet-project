# Тест-план

## Цель

Проверить, что приложение выполняет [пользовательские истории](../docs/02-user-stories.md) и бизнес-правила: деньги не теряются при ошибках, а клиент не видит чужие данные.

## Что тестируем

- REST API: авторизация, роли, валидация, бизнес-правила, коды ошибок
- автоплатежи: исполнение в срок, перенос даты, ошибки
- веб-интерфейс: вход, регистрация, основные сценарии клиента и администратора
- запуск в Docker

Не тестируем нагрузку и безопасность на уровне пентеста. Браузеры, кроме Chrome, проверяем только выборочно вручную.

## Как тестируем

| Вид | Инструменты | Объём |
|---|---|---|
| Юнит- и интеграционные тесты бэкенда | JUnit 5, Mockito, MockMvc | 85 тестов |
| API-тесты | JUnit 5, RestAssured, AssertJ | 99 тестов с учётом параметров |
| UI-тесты | Selenide, Chrome, Page Object | 17 сценариев |
| Ручные проверки | [тест-кейсы](test-cases.md), [чек-лист](checklist.md) | 20 кейсов |

Техники тест-дизайна:
- классы эквивалентности: корректная сумма, ноль, отрицательная, не число, три знака после запятой;
- граничные значения: сумма 0 и 0,01, остаток и остаток + 0,01, лимит 100 000 и 100 000,01, пароль 7, 8, 72 и 73 символа, название счёта 50 и 51 символ;
- переходы состояний: карта активна и заблокирована, пользователь активен и заблокирован, автоплатёж активен и отключён;
- матрица доступа: аноним, владелец, чужой клиент и админ по каждому эндпоинту.

## Окружение

- JDK 17 или новее, Maven, Node.js 20, Chrome.
- Бэкенд для автотестов запускается с профилем `test`. В нём база в памяти, `POST /api/test/reset` сбрасывает данные, `POST /api/test/clock` сдвигает время, а планировщик автоплатежей выключен.
- Перед каждым тест-классом база сбрасывается. Тесты, которые меняют пользователя, регистрируют нового клиента, чтобы не мешать друг другу.
- Адреса берутся из `config.properties`. Группы тестов размечены тегами `api`, `ui`, `smoke`, `security`, например `mvn test -Dgroups=security`.

## Критерии

- Начинаем, когда приложение собирается, `/api/health` отвечает и демо-пользователи входят.
- Заканчиваем, когда все автотесты зелёные, High-кейсы пройдены и нет открытых критичных багов.
- Приостанавливаем, если не стартует бэкенд, не работает вход или больше 20 % тестов падают по одной причине.

## Риски

- Утечка данных между клиентами — закрыта security-тестами на каждый тип объекта.
- Тесты автоплатежей зависят от даты — время на сервере можно сдвигать.
- Нестабильные UI-тесты — локаторы по `data-testid`, ожидания Selenide, отдельные пользователи на тест.

Результаты смотрим в Allure-отчёте, найденные баги — в [bug-reports.md](bug-reports.md).
